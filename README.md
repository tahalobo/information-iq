# موقع الإمبراطورية العراقية

الموقع الرسمي لشبكة قنوات الإمبراطورية العراقية (المعلومات، الأخبار، الألعاب، الموسيقى، الأنمي، الرياضة) وصفحة [@information_1q](https://www.instagram.com/information_1q/). هو موقع ثابت (HTML/CSS/JS) بلا سيرفر وبلا قاعدة بيانات.

## كيف أعدّل المحتوى؟

- **الروابط والأرقام** (متابعين، إيميل، واتساب): `assets/js/config.js`
- **المعلومات والأخبار والإنجازات وأسئلة الاختبار**: `assets/js/data.js`
  - لإضافة معلومة انسخ أي عنصر داخل `FACTS` وغيّر `id`، بالإنجليزية وبدون مسافات.
  - النص يُكتب داخل `body` بوسوم HTML بسيطة: `<p>` و`<h2>` و`<ul><li>`.
  - أضف أسئلة للمعلومة في `QUIZ` واربطها بها عبر `fact: "id"`.
- **استلام رسائل نموذج التواصل في كروب تليغرام**: انسخ `scripts/contact-form.gs` إلى سكربت Google مجاني (script.google.com) وضع توكن البوت في خصائصه، ثم ضع رابطه في `formEndpoint`. الخطوات أعلى الملف نفسه. التوكن لا يظهر في الموقع أبداً. بدونه يجهّز الموقع الرسالة ويرسلها المتابع عبر الدايركت أو تليغرام.

## نسخة النشر (dist)

```bash
node scripts/build-dist.mjs
```

تنسخ ملفات الموقع فقط إلى `dist/` (بلا `scripts` و`worker` وملفات الاختبار والفيديو)، وتعطي `sw.js` رقم إصدار جديداً من بصمة المحتوى حتى يحدّث الزوار ذاكرتهم. أضف `--pages` لتشغيل `build-pages.mjs` قبلها. ولضغط JS وCSS وJSON ثبّت esbuild مرة واحدة: `npm i --no-save --no-package-lock esbuild`. للمعاينة: إعداد `dist` في `.claude/launch.json` (المنفذ 5580). المجلد `dist/` مستثنى من git.

## التشغيل محلياً

```bash
python .claude/dev_server.py
```

ثم افتح http://localhost:5500

## النشر مجاناً

- **GitHub Pages** (الطريقة المعتمدة، وبها يتحدث الموقع وحده من القناة كل نصف ساعة):
  1. ارفع المجلد إلى مستودع **عام** (Public). النشر والتشغيل كل نصف ساعة مجانيان للمستودعات العامة فقط.
  2. من Settings ← Pages ← Source اختر **GitHub Actions**.
  3. من Actions ← Telegram sync ← Run workflow شغّله أول مرة.
  4. الموقع يظهر على `https://<اسم-الحساب>.github.io/<اسم-المستودع>/`.
  - الملفات التي لا تُرفع (فيديو الإعلان، ملفات التجارب، خطة الموقع) محددة في `.gitignore`.
- **Netlify** بديلاً: اسحب المجلد كاملاً إلى https://app.netlify.com/drop (لكن بلا تحديث تلقائي).

بعدها يمكنك ربط دومين خاص بالموقع، مثل `information-iq.com`.

## المزامنة التلقائية مع قناة تليغرام

الموقع يسحب منشورات القناة [t.me/informationss_iq](https://t.me/informationss_iq) ويفرزها تلقائياً. ولا يحتاج ذلك أي توكن أو API مدفوع.

| النوع | كيف يُعرف |
|---|---|
| **معلومة** | نص معلوماتي أطول من الحد الأدنى، وفيه سنوات وأرقام وكلمات مثل «يُعد» و«اكتشف» و«القرن» |
| **فعالية** | مسابقات واستفتاءات وأسئلة «صواب أو خطأ» وإعلانات الفائزين. منشورات المسابقة الواحدة تُجمع في **بطاقة واحدة** |
| **خبر** | مثل «أُعلن اليوم» و«فاز» و«اليوم العالمي» |
| **شعر وأدب** | نص قصير بتشكيل كثيف وأبيات |
| **سؤال للنقاش** | سؤال قصير مثل «هل الروح تحمل الجسد…؟» |
| **مستبعد** | ترويج القنوات الأخرى، والمكرر، والأقصر من الحد الأدنى |

يعرف السكربت أيضاً نوع الوسائط: صورة أو ألبوم أو فيديو أو نص. يحفظ الصور محلياً، ويعرض الفيديو عبر مشغّل تليغرام الرسمي. ويستخرج عنواناً لكل منشور، ويحدد قسمه (تاريخ العراق، علوم، فضاء…).

**التشغيل يدوياً:**

```bash
node scripts/telegram-sync.mjs              # تحديث آخر المنشورات
node scripts/telegram-sync.mjs --pages 40   # سحب تاريخ القناة (≈ 800 منشور)
node scripts/telegram-sync.mjs --reclassify --report   # إعادة الفرز بعد تعديل القواعد
```

**التشغيل التلقائي:** بعد رفع الموقع إلى GitHub يعمل ملف `.github/workflows/telegram-sync.yml` كل نصف ساعة مجاناً، ويحدّث الموقع وحده.

**التحكم** من ملف `scripts/telegram.config.json`:
- `minFactLength`: الحد الأدنى لطول المعلومة (250 حرفاً افتراضياً).
- `overrides`: لتصحيح أي منشور يدوياً، مثل `"15220": { "type": "news" }` أو `{ "hide": true }` أو `{ "title": "عنوان أفضل" }`.

صفحة `channel.html` فيها «وضع المدير»، وهو يعرض سبب تصنيف كل منشور ودرجة الثقة.

## فروع الإمبراطورية: الأخبار والألعاب والموسيقى والأنمي والرياضة

الأمر `node scripts/branches-sync.mjs` يسحب القنوات الخمس، ويعرضها في صفحة `branch.html` وفي الرئيسية وفي البحث. ويعمل تلقائياً مع مزامنة GitHub كل نصف ساعة.

| الفرع | القناة |
|---|---|
| إمبراطورية الأخبار | [t.me/newss_iq](https://t.me/newss_iq) |
| إمبراطورية الألعاب | [t.me/gamersss_iq](https://t.me/gamersss_iq) |
| إمبراطورية الموسيقى | [t.me/mussic_iq](https://t.me/mussic_iq) |
| إمبراطورية الأنمي | [t.me/anime_iq3](https://t.me/anime_iq3) |
| إمبراطورية الرياضة | [t.me/sportts_iq](https://t.me/sportts_iq) |

**ما يظهر:** الخبر الذي يصلح عنواناً ووصفاً فقط. أي أن طول النص كله 160 حرفاً على الأقل (`minChars`)، وبعد العنوان وصف لا يقل عن 70 حرفاً (`minBody`).

**ما لا يظهر:**
- الإعلانات: الاستثمار والبوتات وروابط القنوات الأخرى و«قناتنا الاحتياطية».
- الفعاليات والمسابقات والاستفتاءات وأسئلة «اكتبوا بالتعليقات».
- الخبر ذو السطر الواحد، والدردشة مع المتابعين.
- المحوَّل من قنوات أخرى، والمكرر بين الفروع أو مع قناة المعلومات.

```bash
node scripts/branches-sync.mjs                  # تحديث كل الفروع
node scripts/branches-sync.mjs --report news    # جدول بما قُبل وما رُفض ولماذا
node scripts/branches-sync.mjs --reclassify     # إعادة الفرز بعد تعديل القواعد (بلا إنترنت)
```

**التحكم** من `scripts/telegram.config.json` ← `branches`:
- `minChars` و`minBody`: حدود الطول.
- `maxPosts`: عدد الأخبار المحفوظة لكل فرع (300).
- `list`: القنوات نفسها. لإضافة فرع أضفه هنا، وأضف اسمه ولونه وأيقونته في `window.BRANCHES` داخل `assets/js/data.js`.

صور الفروع تُعرض من تليغرام مباشرة ولا تُحفظ في المستودع، لكي لا يكبر حجمه مع مئات الأخبار يومياً. إذا انتهت صلاحية صورة قديمة يظهر غلاف ملوّن بلون الفرع.

## محرّك التوثيق: مصادر إضافية من الويب لكل معلومة

الأمر `node scripts/enrich-sources.mjs` يبحث عن مصادر لكل معلومة غير منشور تليغرام، ويعرضها في «شهادة التوثيق» داخل صفحة المعلومة.

كيف يعمل:
1. **يفهم موضوع المنشور:** يفحص كل عبارة فيه (من كلمة إلى أربع) مقابل عناوين مقالات ويكيبيديا العربية. العبارة التي لها مقالة هي موضوع، مثل «بنو موسى» و«زنوبيا» و«كتاب الحيل».
2. **يبحث:** في ويكيبيديا العربية ثم مقابلها الإنجليزي، وفي محرك بحث ويب بعنوان المنشور، ثم بأندر كلماته، ثم بالاسم الإنجليزي للموضوع.
3. **يتحقق:** يفتح كل صفحة ويقرؤها، ويقارن كلمات المنشور المميزة وأرقامه بنصّها. لا يقبل الصفحة إلا إذا وجد فيها مقطعاً يروي المعلومة نفسها (`minScore`).
4. **يحفظ:** أفضل 5 مصادر، واحد لكل موقع، مع نوع المصدر (موسوعة، علمي، رسمي، صحافة، موقع) واقتباس قصير ونسبة التطابق، في `scripts/sources-store.json`.

```bash
node scripts/enrich-sources.mjs               # أحدث 25 منشوراً لم يُفحص
node scripts/enrich-sources.mjs --limit 200   # عدد أكبر (لفحص الأرشيف كله على دفعات)
node scripts/enrich-sources.mjs --id 15243    # منشور واحد مع شرح كل خطوة
node scripts/enrich-sources.mjs --force       # إعادة فحص ما فُحص
node scripts/enrich-sources.mjs --stats       # إحصائية
```

**محركات البحث:** ويكيبيديا تعمل دائماً بلا مفتاح. أما بحث الويب فيجرّب DuckDuckGo ثم Brave بلا مفتاح، وهذان يحظران الطلبات الآلية بعد عدد قليل. للحصول على نتائج غوغل نفسها أضف أحد المفاتيح الآتية كمتغير بيئة، وعلى GitHub من Settings ← Secrets and variables ← Actions ← Secrets:

| المفتاح | المصدر |
|---|---|
| `GOOGLE_API_KEY` و`GOOGLE_CX` | Custom Search JSON API من غوغل |
| `SERPER_API_KEY` | نتائج غوغل عبر [serper.dev](https://serper.dev) |
| `BRAVE_API_KEY` | [Brave Search API](https://brave.com/search/api/) |

**التحكم** من `scripts/telegram.config.json`:
- `sources.block`: مواقع لا تريدها مصدراً، مثل `["example.com"]`. مواقع التواصل والمتاجر مستبعدة أصلاً.
- `sources.trusted`: مواقع تثق بها فتتقدّم في الترتيب.
- `sources.minScore`: حد القبول. ارفعه لتشديد التحقق.
- في `overrides`: `"15243": { "sources": [{ "name": "…", "url": "https://…" }] }` لإضافة مصدر يدوياً، و`{ "noSources": true }` لإخفاء المصادر الآلية عن منشور.

التحقق آلي ويقيس تطابق النص، لا صحة المعلومة. المصدر الضعيف يُحذف بـ`block` أو `noSources`.

## صفحة مستقلة لكل منشور (للمشاركة ومحركات البحث)

الأمر `node scripts/build-pages.mjs` يولّد صفحة HTML في `post/` لكل معلومة ومنشور. وفي كل صفحة:
- عنوان ووصف وصورة معاينة، تظهر عند المشاركة في واتساب وفيسبوك وتليغرام.
- المحتوى مكتوب داخل الصفحة ليقرأه غوغل.

ويولّد الأمر أيضاً `sitemap.xml` و`robots.txt`.

روابط المعاينة يجب أن تكون كاملة، لذا ضع رابط موقعك في `scripts/site.config.json`. على GitHub Pages يُحسب الرابط تلقائياً، وللدومين الخاص أضف متغير المستودع `SITE_URL` من Settings ← Secrets and variables ← Actions ← Variables.

**صور المعاينة:** منشورات القناة تستعمل صورها. أما المعلومات المكتوبة يدوياً فلها صور تُرسم مرة واحدة عبر `scripts/og-maker.html`:
1. شغّل الخادم المحلي: `python .claude/dev_server.py`
2. افتح http://localhost:5500/scripts/og-maker.html
3. اضغط الزر، فتُحفظ الصور في `assets/img/og/`.

## الاختبار التلقائي من القناة

الأمر `node scripts/build-quiz.mjs` يولّد نوعين من الأسئلة:
1. **أسئلة من منشورات المعلومات:** «أكمل الفراغ» و«صح أم خطأ». الجواب مأخوذ من نص المنشور نفسه.
2. **أسئلة فعاليات القناة:** استفتاءات وجمل «صواب أو خطأ». تليغرام يخفي الجواب الصحيح عن الصفحة العامة، لذا تُجمع في `scripts/quiz-answers.json`. اكتب جواب أي سؤال في حقل `answer` فيدخل الاختبار:
   - للاستفتاء: رقم الخيار.
   - لصح أو خطأ: `"صح"` أو `"خطأ"`.

الأجوبة المعلّمة بـ `"note": "جواب مقترح، راجعه"` عبّاها المساعد، فراجعها.

في صفحة الاختبار يختار الزائر بين: مزيج، أو أسئلة مختارة، أو فعاليات القناة، أو من منشورات القناة.

## ملاحظات تقنية

- كل أدوات الصور تعمل داخل المتصفح، فلا تُرفع أي صورة إلى أي سيرفر.
  - الاستثناء الوحيد: زر «غوغل لنز»، الذي يرسل الصورة إلى غوغل بطلب من المستخدم.
- إزالة الميتاداتا من JPG وPNG وWebP تتم **بلا إعادة ضغط**، فتبقى البكسلات مطابقة للأصل.
- فحص التسريبات في أداة كلمات المرور يرسل أول 5 أحرف فقط من بصمة SHA-1 إلى Have I Been Pwned، أي بطريقة k-Anonymity.
- المكتبات المستخدمة تُحمّل من CDN:
  - [Lucide](https://lucide.dev) للأيقونات
  - [exifr](https://github.com/MikeKovarik/exifr) لقراءة الميتاداتا
  - [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) لرموز QR
  - [JSZip](https://stuk.github.io/jszip/) للتحميل الجماعي

## نظام SEO (محركات البحث)

كل شيء يُبنى بأمر واحد، ويعمل تلقائياً داخل الـ Action مع كل منشور جديد:

```bash
node scripts/build-pages.mjs   # يولّد الصفحات والخرائط والخلاصات
node scripts/seo-audit.mjs     # يفحص كل الصفحات ويفشل عند أي خطأ
```

| الملف | ماذا يفعل |
| --- | --- |
| `scripts/site.config.json` | `siteUrl`: **القيمة الوحيدة** التي تُبنى منها الروابط المطلقة. غيّرها (ومتغيّر المستودع `SITE_URL`) عند شراء نطاق خاص. |
| `scripts/seo/content.mjs` | عناوين وأوصاف الصفحات الرئيسية، وشرح وأسئلة كل أداة، وقائمة المواضيع وكلماتها. هذا هو الملف الذي تعدّله بيدك. |
| `scripts/build-pages.mjs` | `post/` صفحة لكل خبر/معلومة · `topic/` صفحات الأقسام والمواضيع · `archive/` أرشيف مرقّم · `404.html` · `sitemap*.xml` · `feed.xml` و`atom.xml` · `robots.txt` · حقن `<head>` والبيانات المنظّمة في الصفحات الرئيسية والأدوات (بين `<!-- seo:head -->` و`<!-- seo:body -->`، فلا تعدّل ما بينهما يدوياً). |
| `scripts/seo-audit.mjs` | مدقّق: عنوان/وصف مكرر أو مفقود أو بطول سيئ، canonical، JSON-LD، صور بلا alt، روابط مكسورة، صفحات خارج sitemap. |
| `scripts/build-icons.mjs` | `assets/js/vendor/lucide-subset.js`: الأيقونات المستعملة فقط (نحو 310 من 1700). شغّله بعد إضافة أيقونة جديدة؛ وإن نُسي فالصفحة تحمّل المكتبة الكاملة وحدها عند أول أيقونة ناقصة. |
| `scripts/indexnow.mjs` | يخبر Bing و Yandex بالروابط الجديدة. معطّل حتى تضع متغيّر المستودع `INDEXNOW_ENABLED = true`. |
| `scripts/seo-state.json` | مولَّد: تاريخ آخر تعديل حقيقي لكل صفحة (`lastmod` و`dateModified`). |

لإضافة موضوع جديد: أضف سطراً في `TOPICS` داخل `scripts/seo/content.mjs` ثم أعد البناء. الموضوع الذي يجمع أقل من 4 منشورات لا تُبنى له صفحة.

### معاينة الروابط في مواقع التواصل (Open Graph)

`node scripts/build-pages.mjs` يرسم أيضاً **صورة معاينة 1200×630 لكل خبر وأداة وموضوع وصفحة** في `assets/og/` (JPEG أقل من 300 ك.ب):

- الرسم بمتصفح Chrome بلا واجهة (`scripts/seo/og.mjs`)، فتُشكَّل العربية كما في الموقع. يحتاج محلياً: Chrome أو Edge، ومكتبة `puppeteer-core` (`npm i --no-save puppeteer-core`، أو الموجودة في `ad-video/`). في الـ Action تُثبَّت تلقائياً.
- تزايدي: اسم الملف يحمل بصمة المحتوى. الصورة الموجودة لا يُعاد رسمها، وتغيير العنوان يعطي اسماً جديداً (فتجلبه المنصات من جديد). لإعادة رسم الكل بعد تغيير التصميم ارفع `TEMPLATE_VERSION` في `scripts/seo/og.mjs`.
- الخطوط في `scripts/fonts/` (Reem Kufi و Lalezar و Cairo، برخصة OFL).
- للمعاينة المحلية: افتح `/scripts/share-preview.html` عبر خادم التطوير لترى شكل بطاقة أي صفحة في واتساب وتيليغرام وفيسبوك و X وديسكورد و iMessage.

## الوضع الخفيف (الأداء على الهواتف والأجهزة الضعيفة)

سكربت صغير مضمَّن في `<head>` كل صفحة (والنسخة نفسها في `THEME_BOOT` داخل `scripts/build-pages.mjs`) يقرّر قبل أول رسم هل يعمل الموقع بالوضع الخفيف، ويضع الأصناف `lite rm no-gl` على `<html>`:

- **يُفعَّل تلقائياً** عند: طلب النظام تقليل الحركة، توفير البيانات أو اتصال 2G/3G، ذاكرة 4 غ.ب أو أقل، 4 أنوية أو أقل، أو هاتف/لوح باللمس (ما عدا الهواتف القوية: 8 غ.ب و8 أنوية فأكثر، والآيفون).
- **المراقب** في `assets/js/fx.js`: على الأجهزة التي بدأت بالوضع الكامل يقيس زمن الإطارات بعد التحميل، وإن كان أكثر من 40% منها أبطأ من 30 إطاراً/ث لنافذتين متتاليتين يحوّل إلى الوضع الخفيف ويحفظ ذلك أسبوعاً (`lite-auto`).
- **زر الريشة** في الترويسة (ومفتاح «الوضع الخفيف» في القائمة الجانبية) يبدّل الوضع فوراً بلا إعادة تحميل ويحفظ الاختيار في `localStorage` (`lite` = `on`/`off`)، واختيار الزائر يغلب الكشف التلقائي.

في الوضع الخفيف: لا WebGL (`gl.js` لا يُحمَّل أصلاً، وبدله هالة وشعار ثابتان)، لا تمرير ناعم (`lenis` لا يُحمَّل)، لا `backdrop-filter`، لا حركات لا تنتهي، لا تحويلات ثلاثية الأبعاد للبطاقات، ولا شاشة تحميل. كل القواعد في آخر `assets/css/style.css` تحت `html.lite`.
